# Interventional record sufficiency: novelty and reachability gate

## Decision

`FORMAL_FIRST_PARTNER_GATED`.

The frozen `HC-DU-036E` cloud instrument is viable as a **conditional
instrument test**, but a normal provider result cannot answer the full
physical question. Public interfaces expose the requested job and its
returned result population. The inspected documentation does not promise a
census of every lower-level trigger, retry, invalid or rejected attempt,
selection reason, retained controller/environment memory, and independently
witnessed reset over all of that memory.

That is not a reason to abandon the research. It changes the order:

1. first harden the integrated theorem and evidence contract against the
   closest established work;
2. use the existing IBM pilot only after direct authorization and only if its
   returned-shot result changes a concrete instrument or shot-budget
   decision; and
3. pursue an implementation-complete physical packet only if the formal
   contribution survives and a laboratory can expose the missing boundary.

Do not build another provider adapter merely to obtain the same visibility
ceiling. No standard provider inspected here documents a decisive advantage
over the existing bridge. Do not run another synthetic completion fixture
unless it tests a newly stated formal uncertainty.

## What this means in plain English

Dynamic Unity is asking a stricter question than “can this experiment predict
the next measurement?” Established quantum-process methods already do that
very well.

DU asks whether an independently chosen record contains everything that can
matter to a declared observer under held-out interventions. If it does not,
DU asks for the smallest physically formed repair; if every admissible repair
fails, it asks whether a class-relative physical remainder survives.

The important danger is that a laboratory or provider may return only the
successful rows. Two underlying processes can agree perfectly on every
returned row and still differ among attempts that were filtered, retried, or
never surfaced. Similarly, a reset on the three user qubits does not prove a
reset of controller, detector, route, or environment memory that the
completion class admits. The current software catches that logical gap. It
cannot make an external interface reveal what the interface does not promise.

So the foreseeable wall is not “we need a quantum computer to proceed.” The
next high-information work is local mathematics and literature positioning.
A quantum cloud run is optional calibration. The first genuinely decisive
physical test is collaboration-gated, not compute-gated.

## Can the current computer still teach us something significant?

**Yes—provided the work is theorem-or-absorption work rather than more
simulation plumbing.**

The current computer can still produce three scientifically significant
outcomes:

| local route | significant result available without new hardware |
|---|---|
| Formal translation and hostile prior-art collision | A distinct exact theorem/no-go, or a precise proof that the proposed contribution is already absorbed and should stop. Both materially advance knowledge and prevent wasted experimental work. |
| Exact finite identifiability and counterexample search | A tight bound on when a record can be sufficient, or a minimal pair of processes that no admitted record can distinguish but a held-out intervention can. This can be exact rational, linear-algebraic, convex, or proof-assistant work. |
| Minimum discriminating experiment | A derivation of the smallest instrument, acquisition fields, resets, intervention basis, error budget, and sample complexity that could separate the DU contract from its strongest standard quantum-process null. This is experimental theory, not an experiment. |

Local simulation remains useful only as an implementation kill or
calibration. It cannot establish a physical remainder, because a simulation
can only exhibit consequences of the dynamics and hidden variables placed
inside it. Likewise, no local calculation can by itself show that nature
departs from the best standard quantum-process model.

The external-evidence boundary therefore begins **after**, not before, the
local program has:

1. produced a distinct formal survivor or exact no-go;
2. frozen the minimum physical discriminator and standard null; and
3. shown that neither proof nor existing data can adjudicate it.

If the integrated contract is absorbed or no decision-changing discriminator
survives, stop before hardware. This keeps the path from becoming a long
build toward a wall.

### Default external-hardware posture

Until those local gates prove otherwise, Dynamic Unity must operate under:

```text
external hardware availability = ASSUME_UNAVAILABLE
```

External hardware becomes an eligible dependency only when all four are
recorded:

1. the integrated theorem-or-absorption gate is complete;
2. the minimum physical discriminator and strongest standard null are frozen;
3. local proof, counterexample, simulation, existing-data, and alternative
   experimental-design routes are exhausted for that discriminator; and
4. external hardware is shown to be the irreducible next dependency rather
   than merely a convenient next step.

At that boundary, the owning run writes and reports **one awareness note**:

```text
external path available
what it would decide
why local alternatives are exhausted
minimum access or collaboration required
what local fallback remains
```

That note does not authorize access. Unless Joe separately authorizes the
external path, take the best remaining local route or park the branch. Do not
repeat provider searches, build alternate adapters, or keep reproposing the
same hardware dependency without a genuinely new reopener.

### The not-yet-absorbed candidate

No single primary source was located in this bounded search that combines all
five of these obligations in one adjudicator:

1. an observer-indexed record quotient frozen independently of the target
   answer;
2. every acquisition stratum, including invalid and rejected attempts;
3. a nonempty, target-independent, physically admissible and
   resource-accounted completion/refinement class;
4. verified reset over every retained memory admitted by that class; and
5. one result type distinguishing base reconstruction, Pareto-minimal
   physical repair, class-relative remainder, and incomplete contract.

This conjunction is the candidate DU contribution. “Not located” is not a
novelty verdict. The next formal swing must express it in ordinary
process-tensor, quantum-instrument, statistical-experiment, and system-
identification language and either:

- prove that the integrated contract adds a real theorem or no-go;
- show that it is a useful experimental assurance/data standard even when
  the mathematics is known; or
- find the exact existing construction and stop or merge the claim.

### Provider conclusion

```text

+ shot-joined named results

```

No inspected standard interface documents all four **physical-adjudication**
fields:

```text
all physical triggers/retries
+ invalid/rejected rows and reasons
+ retained-memory inventory
+ independently witnessed reset of every admitted memory
```

This supports a no-new-adapter rule, not a provider impossibility claim.

## Efficient route from here

### 1. Formal contribution test — do next

State a substrate-neutral **Interventional Record Sufficiency Under Selective
Acquisition** theorem or no-go using:

- a process tensor or quantum comb for the multi-time process;
- a declared quantum instrument for the record-forming intervention;
- an acquisition variable \(S\) for every selected/rejected stratum;
- an independently frozen record channel \(R\);
- an admitted intervention set \(\mathcal A\);
- a target-independent resource-ordered completion family \(\mathcal C\);
  and
- a reset/causal-break condition typed over every memory represented in
  \(\mathcal C\).

The first theorem target is not “records create reality.” It is:

> Under which finite-dimensional conditions does the complete selective
> process factor through \(R\), when is there a Pareto-minimal admissible
> refinement, and when does finite experimental access make the comparison
> provably non-adjudicable?

The quickest kill is to translate every term into process-tensor and
statistical-experiment notation and ask whether an existing theorem supplies
the same four-way result. If yes, merge/stop. If no, prove the smallest exact
version before spending on hardware.

### 2. Existing IBM pilot — conditional option

Run only if Joe directly authorizes it and one of these decisions is live:

- whether mid-circuit noise destroys the chosen QND-memory instrument;
- whether the pointer-plus-environment refinement is measurable at a useful
  finite-shot margin;
- whether the reset arm is strong enough to justify a partner proposal; or
- what shot/calibration scale a co-designed experiment would require.

The frozen bridge is sufficient. A second adapter is not currently a better
way to learn those things.

### 3. Partner packet — only after formal survival

If the integrated contribution survives, prepare a one-page acquisition
contract for a laboratory that can expose:

- triggers, retries, invalid and rejected attempts;
- selection and filtering reasons;
- joined controller, route, detector, and calibration state;
- a declared inventory of memories capable of carrying history; and
- a witnessed causal break or reset over that inventory.

Contact, data request, purchase, account use, and hardware submission remain
separate external actions and were not authorized or performed here.

### 4. Valuable fallback if no partner exists

The program does not dead-end:

- prove a no-go showing why returned-shot data cannot certify complete-process
  sufficiency without an acquisition assumption;
- publish the formal four-way adjudicator at a precisely bounded grade if it
  survives collision; and/or
- release the acquisition schema as a research data standard that lets future
  experiments answer the stronger question.

That fallback is only worth a paper if the literature collision establishes a
distinct formal or methodological contribution. Merely renaming process
tensors “records” is not enough.

## Go, stop, and reopen rules

### Go

- Formalize the integrated conjunction in established notation.
- Use the existing IBM pilot when it changes a declared design decision.
- Draft a partner specification only after the formal novelty gate survives.

### Stop

- Stop new provider adapters without a documented observability advantage.
- Stop synthetic completion fixtures without a new formal uncertainty.
- Stop public-data searches for rows that the source pipeline discarded.
- Stop any claim that provider-returned sufficiency implies complete physical
  sufficiency.

### Reopen

- A public or partner packet exposes every attempt, selection reason, admitted
  memory, and complete reset.
- A provider documents a strictly stronger observability contract.
- The formal translation produces a theorem not supplied by process-tensor,
  quantum-instrument, or statistical-experiment work.
- A primary source is found that already supplies the integrated result; in
  that case reopen only to merge or stop the DU claim.
